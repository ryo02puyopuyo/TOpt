# TODD Nullspace 最適化研究ノート

> **目的**: TODD (greedy weight-reduction) アルゴリズムの主要ボトルネックである M4RI Nullspace 計算の高速化  
> **対象回路**: adder_8.tfc (n=95, m=287, T-count: 287→127)  
> **日付**: 2025-04-10

## 1. 問題の特定

### 1.1 実行時間の内訳

`adder_8.tfc` アンシラ無制限での計測結果：

| 処理 | 時間 | 割合 |
|---|---|---|
| χ 行列構築 | 60.7 sec | 7.0% |
| **M4RI Nullspace (PLUQ)** | **783.6 sec** | **90.0%** |
| その他 | 26.7 sec | 3.0% |
| **合計** | **871.0 sec** | 100% |

Nullspace 計算が **全体の90%** を占める。これが唯一の有効な最適化対象。

### 1.2 アルゴリズムの構造

```
for each round:
    for each pair (c1, c2) sorted by Hamming distance:
        x = A[:,c1] ⊕ A[:,c2]                    # n次元ベクトル
        χ = build_chi_matrix(A, x)                # n³×m (packed: ~26K×m)
        NS = mzd_kernel_left_pluq(χ)              # ← ボトルネック (PLUQ分解)
        for each nullspace vector v:
            if v[c1] ⊕ v[c2] == 1:                # ペア条件
                A' = A + x · v^T                   # 行列変換
                if cleanup(A') reduces columns:    # HIT!
                    → 次のラウンドへ
```

## 2. ランダムスケッチ（Random Sketch）

### 2.1 理論

**基本原理**: $\text{Null}(M) \subseteq \text{Null}(M')$（$M'$ は $M$ の行の部分集合）

χ 行列から r = m + δ 行をランダム抽出してスケッチ行列 M' を構築。Null(M') = {0} なら Null(M) = {0} が保証される（対偶）。

**GF(2) のランダム行列の性質**:
- (m+δ) × m のランダム行列がフルランクになる確率: δ=20 で約 99.999%
- 参考: Schwartz-Zippel補題、GF(2)行列のランク分布の研究

### 2.2 実装

CLI フラグ `todd_exp_WXYZ_D`:
- W: Packed Chi (次元圧縮)
- X: AA Table (積テーブル)
- Y: Memoization (キャッシュ)
- Z: Random Sketch
- D: δ値（省略時 = 20）

例: `todd_exp_1001_20` = Packed Chi ON, Sketch ON, δ=20

### 2.3 実験結果

#### 実験 A: 単純な零空間空チェック

| 指標 | 結果 |
|---|---|
| テストしたペア数 | 28,847 |
| リジェクト数 | **0** |
| Full NS empty | **0** (全ペアで零空間が非空) |

> [!IMPORTANT]
> **発見**: χ 行列の零空間は**常に非空**。ランダム行列の理論が想定する「行の独立性」は χ の代数的構造により成立しない。

#### 実験 B: 強化版（ペア条件チェック）

スケッチの零空間で v[c1] ⊕ v[c2] = 1 を満たすベクトルの存在をチェック。

| 指標 | δ=5 | δ=20 | ベースライン |
|---|---|---|---|
| 実行時間 | 883,916 ms | 861,820 ms | 871,003 ms |
| リジェクト数 | 276 | 277 | - |
| **リジェクト率** | **0.96%** | **0.96%** | - |
| T-count | 127 | 127 | 127 |

> [!IMPORTANT]
> **発見**:
> 1. δ を変えてもリジェクト率は 0.96% で収束（δ=5 の時点で rank(sketch) ≈ rank(full)）
> 2. リジェクト率 0.96% は構造的上限であり、スケッチの設計では改善できない
> 3. 99% のミスペアは「零空間に v[c1] ⊕ v[c2] = 1 を満たすベクトルが本当に存在する」ため棄却不可能

### 2.4 結論

> **ランダムスケッチは χ 行列の代数的構造により、リジェクト率が約 1% に留まる。**
> これはフィルター手法全般の構造的限界を示す重要なネガティブ・リザルトである。

## 3. 重要な数学的定理

### 3.1 定理: 「ペア条件を満たせば cleanup は必ず成功する」

**主張**: v ∈ Null(χ) かつ v[c1] ⊕ v[c2] = 1 ならば、変換 A' = A + x · v^T により mp(A') < m が保証される。

**証明**:

x = A[:,c1] ⊕ A[:,c2] とする。v[c1] = 1, v[c2] = 0 の場合（逆も対称的）：

```
A'[:,c1] = A[:,c1] ⊕ x = A[:,c1] ⊕ A[:,c1] ⊕ A[:,c2] = A[:,c2]
A'[:,c2] = A[:,c2]
```

よって A'[:,c1] = A'[:,c2]（列 c1 と c2 が同一になる）。

**逆方向の増加が起きないことの証明**:

- 変更されない列同士（v[j]=0）: 元から独立であり変化なし
- 変更される列同士（v[j1]=v[j2]=1）: A'[:,j1] = A[:,j1] ⊕ x, A'[:,j2] = A[:,j2] ⊕ x。これらが等しいのは A[:,j1] = A[:,j2] のときだけだが、cleanup 済みなので存在しない
- 混合（v[j1]=0, v[j2]=1）: A[:,j1] = A[:,j2] ⊕ x のとき新しい重複が**追加で**生じうるが、これは列数をさらに減らす方向

∴ 列数は必ず減少する。□

### 3.2 系: ミスペアの完全な特徴付け

> **ペア (c1, c2) がミスとなるのは、Null(χ(x)) に v[c1] ⊕ v[c2] = 1 を満たすベクトルが存在しない場合に限る。**

これは同値条件：

> **e_{c1,c2}（位置 c1, c2 だけが 1 のベクトル）が χ(x) の行空間に含まれる**

この判定は、χ の RREF に対する e_{c1,c2} の前進消去（O(m²/64)）で実行可能。

## 4. 提案手法: インクリメンタル行空間追跡

### 4.1 着想

χ 行列は x = A[:,c1] ⊕ A[:,c2] に依存する。異なるペア間で x が 1 ビットだけ変化した場合、χ の行のうち変化するのは全体の **3/n**（n=95 では約 3.1%）のみ。

**残り 96.9% の行は再計算不要。**

### 4.2 χ 行列の変化量の分析

x の位置 k が反転すると、影響を受ける行は α=k or β=k or γ=k のもの：

```
|影響行| = 3n² - 3n + 1 ≈ 3n²
```

各影響行の差分 Δ は閉形式で計算可能（x_k に依存しない既知量のみ）：

```
Δ[k,β,γ][j] = x_β·x_γ ⊕ A_β·A_γ[j] ⊕ x_β·A_γ[j] ⊕ x_γ·A_β[j]
```

### 4.3 アルゴリズム

**データ構造**: GF(2) 上の m 次元行空間の基底（RREF 形式で最大 m 本のベクトル）

```cpp
// 初期化（最初のペアのみフル計算）
basis = echelonize(χ(x_first))

// 以降のペア（x が d ビット変化）
for each flipped bit k in (x_old ⊕ x_new):
    for each affected row (α,β,γ) involving k:
        Δ = compute_delta(k, α, β, γ, A, x)    // O(m/64)
        new_row = old_row ⊕ Δ
        
        if old_row was in basis:
            remove_from_basis(old_row)           // ピボット交代
        add_to_basis(new_row)                    // 前進消去 O(m²/64)

// ペア条件判定
e = e_{c1,c2}
if reduce(e, basis) == 0:
    → MISS
else:
    → HIT確定 → mzd_kernel_left_pluq で変換ベクトル取得
```

#### 行の追加 (add_to_basis)

```cpp
function add_row(r):
    // 基底に対して前進消去
    for i = 0 to rank-1:
        if r[pivot_col[i]] == 1:
            r = r ⊕ basis[i]      // O(m/64) ワード演算
    
    if r == 0:
        return  // 既存の基底で表現可能（従属）
    else:
        // 新しいピボットを発見 → 基底に追加
        basis[rank] = r
        pivot_col[rank] = r の最初の非零ビット位置
        rank++
```

#### 行の削除 (remove_from_basis)

```cpp
function remove_basis_row(i):
    lost_col = pivot_col[i]
    basis[i] を削除、rank--
    
    // 代替ピボットを探す（非基底行の中から）
    for each non-basis row r in χ:
        r_reduced = reduce(r, current_basis)
        if r_reduced[lost_col] == 1:
            add_row(r_reduced)
            return
    
    // 見つからない → ランクが1減少
```

### 4.4 計算量

| 方式 | 計算量 | n=95, m=200 |
|---|---|---|
| **フル再計算（現在）** | O(r · m²/64) | ~16M word ops |
| **差分更新（d=1 bit）** | O(n² · m²/64) | ~5.6M word ops |

高速化率 = 3w/d（w = x の重み、d = x の変化ビット数）:

| x の重み w | 変化ビット d | 高速化率 |
|---|---|---|
| 10 | 1 | **30x** |
| 10 | 2 | **15x** |
| 50 | 1 | **150x** |
| 50 | 5 | **30x** |

> [!TIP]
> **終盤のラウンド（w が大きい = 最もボトルネックな部分）で最大効果。** Round 48-50 が数分→数十秒に短縮される可能性。

### 4.5 前提条件

1. **ペアの処理順序**: x ベクトルの近さでソート（Gray code 的順序）
   - 現在はハミング距離の昇順 → x の近さでの副次ソートを追加
   
2. **HIT 時の処理**: HIT が確定した場合のみ χ 全体を再構築して mzd_kernel_left_pluq を呼ぶ
   - HIT は全ペアの ~0.2% なのでオーバーヘッド軽微

## 6. 実験で得られた重要な知見

1. **χ 行列の零空間は常に非空**: ランダム行列理論の「フルランク確率」は χ の代数的構造には適用できない

2. **リジェクト可能なペアは全体の約 1%**: これは χ 行列の構造的上限であり、フィルター手法では改善不可能

3. **ペア条件 v[c1] ⊕ v[c2] = 1 は HIT の十分条件**: cleanup は必ず成功する（定理 3.1）

4. **PLUQ 分解が計算時間の 90% を占める**: Kernel 抽出やペアチェックのコストは無視可能

5. **終盤のラウンドが実行時間を支配**: Round 48-50 だけで全体の 60%+ を消費
